This page pulls the key diagrams out of the current design docs so you can review the deploy model, import contracts, and buyer claw flow in one place. The canonical written specs still live in the markdown files next to this viewer.

Bring Your Own Merchants

One engine, many deploys. The deploy owner should supply config, merchant manifests, and brand assets without editing engine code.

    A[Deploy Owner] --> B[Deploy Config]

    C --> E
    D --> E
    E --> F[D1 Control Plane]

Offer Lifecycle

Offers stay structured: claimed merchant, internal review, active in D1, then exported to country-scoped public artifacts in R2.

flowchart LR
    A[Claimed Merchant] --> B[Offer Draft]
    B --> C[Internal Review]
    C --> D[Active Offer in D1]
    D --> E[Export to R2 by Country]
    E --> F[Country discovery pages]
    E --> G[Offers-first discovery input]

Buyer Claw Request Flow

This is the loop the product has to prove first: shortlist merchants, resolve MCP, build cart, hand off checkout.

flowchart TD
    A[Buyer claw asks for coffee] --> B[LobsterBazaar Worker]
    B --> C[R2 country index]
    B --> D[R2 merchant records]
    C --> F[Shortlist merchants]
    D --> F
    F --> G[Select merchant]
    G --> H[Resolve merchant MCP endpoint]
    H --> I[Merchant Storefront MCP]
    I --> J[Search catalog]
    I --> K[Check policies]
    J --> L[Pick products]
    L --> M[Update cart with lb_source__]
    M --> N[Checkout URL]
    N --> O[Return handoff to owner]

Merchant MCP Resolution

The service resolves across many merchants, but each merchant only needs one Storefront MCP endpoint. In most cases the endpoint can be derived from the shop domain.

flowchart LR
    A[Merchant record] --> B[storefront_mcp_url]
    A --> C[store_domain]
    A --> D[store_url]
    E[merchant connect endpoint] --> F[Resolution rule]
    F --> B
    F --> G[derived from store_domain]
    F --> H[derived from store_url host]
